# فيديو ستيكمان سريع مع صوت AI

هذا المسار هو البديل الجديد للتجارب السابقة. يجمع الشخصية الكرتونية، التعابير والإيماءات، لوحات الشرح والترجمة والصوت في MP4. يعمل الرسم والصوت الافتراضي على CPU. لا يستخدم نموذج فيديو واقعي.

## أسرع تجربة على Colab

1. نزّل ZIP المستودع من GitHub، وفكّه على جهازك للحصول على الدفتر.
2. افتح Colab ثم **File → Upload notebook** وارفع `04_fast_stickman.ipynb`.
3. اختر `reviewed_example` لأول تجربة. شغّل الخلايا وارفع ZIP الكود عند الطلب.
4. اختر العربية أو الإنجليزية. يُستخدم مثال مراجع جاهز لتجربة الشكل والسرعة.
5. شاهد الفيديو، واسمع الصوت، ثم نزّل MP4. النتائج محفوظة على Drive.

لوضع `idea` اختر CPU أو T4 GPU اختياريًا، ثم أعد تشغيل خلية التثبيت وأدخل الفكرة والإجابات الخمس. يختار `AI_DEVICE=auto` الجهاز المتاح؛ ويمكن إجباره على CPU. تُثبت متطلبات GGUF أو Torch حسب الجهاز في بيئة معزولة. التنفيذ الكامل للدفتر على تخصيص Colab فعلي لم يُختبر هنا؛ الاختبارات المحلية كانت على Linux وCPU.

التثبيت والتنزيل الأول يستغرقان وقتًا إضافيًا. النموذج الصوتي لكل لغة صغير نسبيًا، أما نموذج النص فتنزيله أكبر. لا يتكرر تنزيل الملفات لكل فيديو في الجلسة نفسها، ويمكن حفظ أصوات Piper على Drive.

## التشغيل المحلي

Python 3.12 وLinux، وffmpeg وخط عربي مثل DejaVu Sans:

```bash
python -m pip install -r requirements/presenter.txt
python -m voice2reel.presenter --script examples/fast_presenter/semicolon_ar.json --output outputs/my-video
```

السكربت المرفق لهذا المثال مكتوب ومراجع مسبقًا، وليس نتيجة نموذج النص. الصوت يُنتَج فعليًا بواسطة Piper. للإنجليزية استعمل `semicolon_en.json`.

لتوليد سكربت من فكرة على CPU:

```bash
CC=gcc CXX=g++ CMAKE_ARGS="-DGGML_CUDA=OFF -DLLAMA_CURL=OFF" CMAKE_BUILD_PARALLEL_LEVEL=2 python -m pip install --no-binary llama-cpp-python -r requirements/director-cpu.txt
python -m voice2reel.presenter --idea "ثلاث نصائح لتعلم البرمجة" --interactive --device cpu --output outputs/from-idea
```

تثبيت GGUF قد يحتاج CMake ومترجم C/C++. يستخدم المشروع Qwen3 4B المضغوط، ويمكن تمرير `--gguf-model /path/to/model.gguf` لملف مطابق للبصمة المثبتة. هذا هو نموذج المشروع المفتوح الأوزان، ولا تُرسل الفكرة إلى موديل المحادثة الخاص بالمساعد.

الأعلام البديلة للأسئلة هي `--audience` و`--duration` و`--language ar/en` و`--facts` و`--visual-focus`. أدخل الحقائق الأساسية في `--facts`، خصوصًا للمحتوى التعليمي. فحص JSON لا يضمن صحة المعلومات أو سلامة الصياغة؛ راجع النص قبل النشر.

## السرعة: ماذا قِيس؟

على جهاز بحد نواتين CPU، بعد تنزيل الأوزان:

- مثال عربي مراجع أنتج نحو 31 ثانية من الفيديو في نحو 10 ثوانٍ، مع توليد صوت جديد والرسم.
- تجربة فعلية من فكرة كتبت السكربت بنموذج Qwen3 ثم ولّدت الصوت والفيديو في نحو 54 ثانية لعينة مدتها نحو 14 ثانية. كتابة النص أخذت معظم الوقت.
- إعادة الطلب نفسه استغرقت نحو 0.2 ثانية من سطر الأوامر لأنها أعادت ملفًا موجودًا صالحًا، لا فيديو جديدًا.
- الصوت الإنجليزي والرندر اختُبرا أيضًا فعليًا.

توجد القياسات الخام في `examples/fast_presenter/benchmark.local.json`. تجربة النص الفعلية محفوظة في `actual_ai_run` مع الرد الخام والسكربت وتوقيتات الصوت. هذه عينة وظيفية وليست معيارًا للجودة العربية أو ضمان زمن لكل جهاز.

التغييرات التي قللت الانتظار: طلب نصي واحد بدل سلسلة مخرج/كاتب/محاولات متعددة، توليد صوت محلي خفيف، كاش مستقل لكل مرحلة، ورسم 2D بخلفيات ونصوص وأجزاء وجه محفوظة. محاولات النص الافتراضية واحدة؛ استعمل `--text-attempts 2` إذا أردت محاولة تصحيح إضافية عند فشل البنية.

## تعديل الفيديو دون إعادة كل المراحل

افتح `outputs/my-video/script.json` وعدّل النص أو المشاهد، ثم:

```bash
python -m voice2reel.presenter --script outputs/my-video/script.json --output outputs/my-video
```

- تغيير الكلام يعيد الصوت والفيديو.
- تغيير العنوان أو الإيماءة أو اللوحة مع ثبات الكلام يعيد الرسم فقط.
- تغيير `--profile` يعيد الفيديو ويستعمل الصوت المحفوظ.
- تغيير الفكرة أو الحقائق يعيد كتابة النص. لإبقاء تعديلاتك اليدوية استخدم `--script` بدل `--idea`.
- إذا تغيرت الملفات أو تلفت، لا تُستخدم بصمت كأنها نتائج سليمة.

لا تشغّل عمليتين على مجلد الإخراج نفسه؛ يُرفض الطلب الثاني فورًا بدل خلط الملفات. يتقدم `progress.json` بين مراحل الكتابة والصوت والرسم، ويسجل الخطأ عند الفشل. يبقى الفيديو السابق محفوظًا إذا فشل الرندر الجديد، لذلك افحص حالة العملية قبل اعتبار الملف ناتج الطلب الحالي.

## المشاهد المدعومة

كل مشهد له `narration` و`caption`، ويمكن ضبط:

- `gesture`: present, point, think, shrug, thumbs_up, wave.
- `emotion`: neutral, happy, surprised, concerned, thinking.
- `camera`: wide, medium, close.
- `visual.kind`: none, list, flow, compare, code؛ مع `items` أو `code` حسب النوع.

الـAI يكتب التعليق والعناوين وتسميات اللوحات، ويترجم المحرك هذه البيانات إلى حركات العرض. لا يطلب من الموديل رسم كل فريم أو اختراع rig. يمكن اختيار الحركات والتعابير صراحة في سكربت مراجع. تغيير الإيماءة يُمزج مع السابقة، وتتضمن الحركة عودة وإعادة تأكيد، مع رمش ونظرات وحركة فم مرتبطة بطاقة الصوت.

الترجمة مقسمة إلى عبارات بتوقيت تقديري، وتحريك الفم ليس مزامنة فونيمات. اللقطة القريبة تركز على الشخصية وتخفي اللوحة الجانبية. الكود يُرسم كما هو ولا يُنفّذ؛ اللوحات صغيرة، وتُختصر الأسطر الطويلة بعلامة حذف. استخدم مقاطع قصيرة مقروءة.

المقاس السريع 540×960 و24 FPS. خيار `quality` يخرج 720×1280 و30 FPS. الشخصية ثابتة التصميم، ومحرك الحركة ذو مفردات محددة؛ لا يدعم الآن تفاعلات مفتوحة أو عدة شخصيات. مدة الطلب تقدير للكتابة؛ طول الصوت الفعلي يحدد طول الفيلم.

## الأصوات والتراخيص

الوضع السريع يستعمل Piper: Kareem للعربية الأردنية وLessac للإنجليزية الأمريكية. النبرة مختلفة عن XTTS، وتحتاج الاستماع والمراجعة، خصوصًا الأسماء والمصطلحات.

للاستنساخ أو أصوات XTTS:

```bash
python -m pip install -r requirements/voice.txt
python -m voice2reel.presenter --script script.json --voice-engine xtts --reference voice.wav --output outputs/cloned
```

هذا الوضع أبطأ، ولا تمثله قياسات Piper. لا يُدعم الاستنساخ في وضع Piper. راجع ترخيص Piper GPL-3.0 وبطاقات أصواته ومصادر بياناتها؛ التوفر للتنزيل ليس تصريحًا عامًا بالاستخدام التجاري. XTTS يخضع لـCPML غير التجاري.
