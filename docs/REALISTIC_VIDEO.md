# إنشاء فيديو واقعي من فكرة مكتوبة

المسار الجديد: **فكرة مكتوبة، فيديو مرجعي اختياري، خمسة أسئلة، خطة إخراج، سكربت، صوت، مشاهد مولّدة، فيديو نهائي**.

## التشغيل على Colab

1. من GitHub نزّل المستودع: **Code → Download ZIP**، ثم فك الضغط على جهازك.
2. افتح [Colab](https://colab.research.google.com/)، ثم **File → Upload notebook** واختر `notebooks/03_realistic_video.ipynb`.
3. اختر **Runtime → Change runtime type → T4 GPU** إن كان متاحًا.
4. شغّل الخلايا بالتسلسل. ارفع ZIP المستودع الأصلي في خلية الكود، واربط Drive لحفظ النتائج.
5. اكتب الفكرة وأجب عن الأسئلة الخمسة. الفيديو المرجعي مستقل واختياري.
6. راجع `plan.json` و`script.json`، ثم ولّد الصوت واستمع إليه.
7. ولّد أول لقطة وشاهدها، ثم شغّل خلية بقية الفيديو إن كانت مناسبة. نزّل `video.mp4`.

المسار يستهدف تجربة صغيرة على T4؛ **لم يُشغّل الفيديو الكامل على T4 هنا**. البداية 288×512 و24 إطارًا في الثانية و40 خطوة إزالة ضوضاء. هذه دقة معاينة وليست جودة نهائية احترافية. يمكن تجربة 576×1024 مع ذاكرة أكبر.

تحتاج تنزيلات النماذج إلى مساحة كبيرة؛ احتفظ بنحو 40 GB فارغة. تستخدم المراحل عمليات مستقلة: يخرج Qwen قبل تحميل XTTS، ويخرج XTTS قبل LTX. داخل مرحلة الفيديو تُشفّر البرومبتات بواسطة T5 مضغوط إلى 4-bit، ثم تُحرّر ذاكرته قبل تحميل نموذج الفيديو. هذا تصميم لتقليل استهلاك الذاكرة، وليس قياسًا يضمن ملاءمة أي جلسة مجانية.

## ماذا تعني «فريم فريم» هنا؟

نطلب من المخرج وصف اللقطة وحركتها وبدايتها ونهايتها، ثم يولّد نموذج الفيديو مجموعة الإطارات مترابطة. يسجل `timeline.json` أرقام إطارات البداية والنهاية لكل مقطع، وتحدد مدة الصوت الفعلية طول المشهد. كتابة برومبت مستقل لكل إطار ليست آلية هذا النموذج.

اللقطات الطويلة تُقسم إلى أجزاء لا تتجاوز خمس ثوانٍ افتراضيًا. يأخذ الجزء المكمل آخر صورة من الجزء السابق. لا يوجد ضمان بأن النموذج سينفذ كل فعل عند إطار بعينه. وصف الاستمرارية يساعد، لكن توليد لقطات مستقلة قد يغير وجه الشخصية أو تفاصيل المكان.

## حدود الفيديو المرجعي

تُستخرج أول صورة من المرجع لتكييف بداية أول لقطة. Qwen هنا نصي؛ **لا يشاهد الفيديو ولا يحلل حركة الكاميرا أو الأسلوب فيه**. أجب عن سؤال المكان والشخصيات لوصف ما تريد استلهامه. قد تتعارض صورة مرجعية مختلفة جدًا مع البرومبت.

العينة الصوتية مختلفة عن الفيديو المرجعي: ليست مطلوبة للصوت الجاهز، وتُستخدم فقط عند اختيار استنساخ الصوت.

## الموديل الأقوى وتجربة CPU

مسار الفيديو الواقعي يستخدم **Qwen3-4B-Instruct-2507** للإخراج والسكربت. بقي نموذج 1.5B في دفتر التدريب لتقليل متطلبات QLoRA. أوزان تخصيص 1.5B لا تصلح للنموذج الجديد، ولا تُحمّل تلقائيًا في المخرج الجديد.

على Colab يُحمّل Qwen3 4B بضغط NF4 على GPU، وينتهي تشغيله قبل XTTS وLTX. على CPU توجد نسخة Q4_K_M من Unsloth للنموذج الرسمي عبر llama.cpp، مع فحص SHA-256 للأوزان. هذا ضغط مختلف عن NF4؛ لا نتوقع مخرجات متطابقة بين الجهازين.

```bash
python -m pip install -r requirements/director-cpu.txt
python -m voice2reel.director --backend gguf --device cpu --threads 2 --brief examples/realistic_semicolon/brief.json --output outputs/realistic
```

ملف GGUF حجمه نحو 2.50 GB، ويُنزّل تلقائيًا. يمكن تحديد ملف سبق تنزيله باستخدام `--gguf-model`. تثبيت llama-cpp-python قد يتطلب CMake ومترجم C/C++ على بعض الأنظمة. هذا المسار مخصص للتخطيط والسكربت فقط؛ **LTX يحتاج GPU**.

إذا كانت عجلة llama-cpp-python الجاهزة غير متوافقة مع Linux عندك، ثبّت GCC/G++ ثم ابنِ الحزمة من مصدرها:

```bash
CC=gcc CXX=g++ CMAKE_BUILD_PARALLEL_LEVEL=2 python -m pip install --no-binary llama-cpp-python -r requirements/director-cpu.txt
```

## الملفات الناتجة

| الملف | المحتوى |
|---|---|
| `brief.json` | الفكرة والإجابات ومسار المرجع |
| `director.trace.json` / `script.trace.json` | إجابات الموديل الخام وأخطاء التحقق |
| `plan.json` | استمرارية الشخصية وخطة اللقطات |
| `script.json` | السكربت العربي أو الإنجليزي |
| `narration.wav` / `narration.json` | الصوت وتوقيت كل مقطع |
| `timeline.json` | حدود الإطارات والبرومبتات |
| `clips/` | المقاطع المولدة القابلة للاستئناف |
| `video_generation.json` | النموذج والإعدادات والبذور وبصمات الملفات |
| `video.mp4` | المشاهد مع الصوت والعناوين |

إذا عدّلت السكربت، أعد توليد الصوت. يتحقق التجميع من تطابق النص واللغة والتوقيت، ويرفض الصوت القديم أو المقطع القصير. تعديل الخطة أو إعدادات الفيديو يغيّر توقيع التوليد ويعيد المقاطع بدل استخدام نتائج غير مطابقة.

## ما الذي اختُبر؟

اختُبرت عمليات Qwen وXTTS الأساسية على CPU، والتوقيت، والعناوين العربية، وترميز H.264/AAC وفك ترميزه. اختُبرت واجهة LTX بأوزان صغيرة عشوائية في حالتي النص والتكييف بصورة؛ هذه **اختبارات برمجية وليست نتيجة مرئية من النموذج الحقيقي**.

الجهاز الحالي بلا GPU. لذلك لا يوجد حتى الآن فيديو واقعي جديد من أوزان LTX الفعلية، ولا قياس لذاكرة T4 أو زمنها. الفيديو القديم هو تجربة الستيكمان فقط. لا يوجد موديل لا يخطئ، ونجاح JSON لا يعني صحة الشرح أو جودة الصورة.
